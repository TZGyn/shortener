# AGENTS.md

Kon.sh is an open-source URL shortener with analytics. This is a **two-service monorepo**:

- `frontend/` - SvelteKit 2 + Svelte 5 (runes) dashboard/API, built with Bun, deployed via Docker/fly.io.
- `redirect/` - Go 1.22 + Fiber hot-path redirect service that resolves short codes and records visitor analytics.

Both services share **one PostgreSQL database**. There is no test suite, no Makefile, and no linter beyond Prettier.

## Commands

### Frontend (`frontend/`)

Package manager is **Bun** (`bun.lock`; `.npmrc` has `engine-strict=true`). The README shows `npm run dev` but scripts run identically under Bun.

```bash
bun install
bun run dev        # vite dev
bun run build      # vite build
bun run check      # svelte-kit sync && svelte-check (typecheck)
bun run lint       # prettier --check .
bun run format     # prettier --write .
```

Database (Drizzle):

```bash
bun run db:generate   # drizzle-kit generate -> writes SQL into frontend/drizzle/
bun run db:migrate    # drizzle-kit migrate  -> applies migrations
bun run db:push       # drizzle-kit push     -> push schema without migration files
bun run migrate       # bun ./src/lib/db/migrate.ts (alternate programmatic migrate)
```

`DATABASE_URL` must be set for any of the db commands (`drizzle.config.ts` reads `process.env.DATABASE_URL`).

### Redirect (`redirect/`)

```bash
go mod download
go run main.go     # or: air run main.go
go build           # produces ./main (or ./run-app in Docker)
```

Run it from inside `redirect/`: `main.go` loads `./regexes.yaml` and `./data/GeoLite2-City.mmdb` relative to the working directory. On first run, if the GeoLite2 DB is missing it downloads it from MaxMind (requires `GEOIPUPDATE_ACCOUNT_ID` and `GEOIPUPDATE_LICENSE_KEY`) and refreshes it weekly via an in-process cron.

### Regenerating the redirect DB layer (important)

`redirect/db/` is **generated by sqlc** and must not be hand-edited. The query source is `redirect/db/query/query.sql`; the schema source is `../frontend/drizzle` (see `redirect/sqlc.yaml`). After changing the Drizzle schema or the SQL queries, regenerate from `redirect/`:

```bash
sqlc generate
```

This is the only link between the two services' data models - keep them in sync.

## Architecture & data flow

### Redirect service (`redirect/main.go`)

- Fiber app on port `3000`, rate-limited to 20 req/min per IP, with a global logger.
- Single dynamic route `GET /:code`:
  - If the request `Hostname` equals `APP_URL` (default `kon.sh`) it looks up via `GetShortener`; otherwise it treats the host as a custom domain and uses `GetShortenerWithDomain`.
  - Resolves the destination (or a presigned S3/Tigris download URL when `is_file_upload` is true).
  - Applies iOS/Android OS-specific link overrides based on `useragent` + `uap-go`.
  - Skips analytics for bots, and dedupes visitors per IP+shortener for 1 hour using an in-memory `go-cache` keyed `ip + "_" + shortenerId`.
  - Geolocates the IP with GeoLite2, parses UA/referer, and inserts a `visitor` row.
- Unknown/invalid codes redirect to `<FALLBACK_URL>/qr/invalid` (default `https://app.kon.sh/qr/invalid`).
- On the app domain, custom-code lookups require `project.enable_custom_domain = false` (personal/non-custom-domain links); custom domains require `enable_custom_domain = true` and a matching `custom_domain`.

### Frontend (`frontend/`)

- SvelteKit route groups: `(app)/dashboard/*` (authenticated app), `(auth)/*` (login/signup/email-verification), `(public)/*` (landing, pricing, public QR at `/url/[id]/qr`), plus `api/*` and `webhook/*`.
- `src/hooks.server.ts` is the auth gate: any path starting with `/dashboard` or `/api` requires a valid Lucia session (else `303` to `/login`); `/login` and `/signup` redirect already-authenticated users to `/dashboard`. Consequently **`event.locals.user` is guaranteed non-null inside `/api` and `/dashboard` server code**.
- Auth stack: Lucia with the Drizzle Postgres adapter, `argon2` for password hashing, Google OAuth via `arctic` (`/login/google` and `/login/google/callback`).
- Forms use `sveltekit-superforms` + `zod` adapters. Each route keeps a co-located `schema.ts` (e.g. `links/schema.ts`, `settings/schema.ts`).
- Route-local components live in a `(components)/` folder inside the route directory.
- UI is shadcn-svelte (`bits-ui`), Tailwind, `lucide-svelte` icons. `components.json` maps aliases: components -> `$lib/components`, utils -> `$lib/utils`, ui -> `$lib/components/ui`, hooks -> `$lib/hooks`.
- DB access is Drizzle ORM. The `db` client and `schema` live in `src/lib/db/`. Prefer the relational query API (`db.query.project.findFirst({ where, with })`) for reads, as seen throughout the routes.

### Cross-cutting services

- **Payments**: Polar.sh is the current provider (`@polar-sh/sveltekit`, `/api/polar/checkout`, `/api/polar/portal`, `/webhook/polar`). Stripe is legacy, still present behind `PAYMENT_PROVIDER=stripe` (`/webhook/stripe`, `PRIVATE_STRIPE_*`). Webhooks flip `user.plan` between `free` and `pro` based on the configured pro price id.
- **File uploads**: Tigris/S3 via presigned URLs (`api/project/[project_id]/file`). Object keys are `"{userId}/{projectId|personal}/{filename}"`. The S3/Tigris webhook (`/webhook/s3`, `/webhook/tigris`) parses that key, then creates/updates `file` rows and a `shortener` row with `is_file_upload = true`. Uploads are gated to `plan !== 'free'`, max 1000 files/project and 100 GB/user.
- **Custom domains**: `src/lib/server/domain.ts` dispatches to a hosting provider client (`railway.ts` or `flyio.ts`) based on `PRIVATE_HOSTING_PROVIDER`. It is a no-op returning success when no provider is configured.
- **Email**: `src/lib/server/email.ts` dispatches to Resend (`PRIVATE_MAIL_PROVIDER=resend`) for email verification tokens.

## Data model notes

- Drizzle schema (`frontend/src/lib/db/schema.ts`) is the source of truth. Tables: `user`, `shortener`, `file`, `project`, `visitor`, `session`, `email_verification_token`.
- `user.plan` is a typed union `'free' | 'pro' | 'owner'`.
- `project.domain_status` is `'pending' | 'verified' | 'disabled'`.
- Drizzle column names are snake_case in the DB but camelCase in TS; some are inconsistent (e.g. `shortener.is_file_upload`/`file_path`, `project.qr_background` vs `project.qrCornerSquareStyle`). Match the exact field name in `schema.ts`.
- `frontend/src/lib/db/types.ts` exposes `InferSelectModel` aliases (`User`, `Shortener`, `Project`) - reuse these rather than redeclaring types.

## Conventions & gotchas

- **Env vars**: frontend code reads env via `$env/dynamic/private` (and `$env/dynamic/public` for `PUBLIC_*`), not `$env/static/*`. Private vars are prefixed `PRIVATE_` and public ones `PUBLIC_` (see `frontend/.env.example`). The redirect service uses plain names (`DATABASE_URL`, `APP_URL`, `FALLBACK_URL`, `AWS_*`, `GEOIPUPDATE_*`); the two `.env.example` files are independent.
- **Prettier**: tabs, no semicolons, single quotes, `trailingComma: all`, `printWidth: 70`, `bracketSameLine: true`, with svelte and tailwind plugins. Run `bun run format` before finishing; `bun run lint` is just a Prettier check.
- **Typecheck**: `bun run check` (svelte-check). TS is strict with `noErrorTruncation`.
- **Prototype extensions**: `src/lib/utils.ts` monkey-patches `String.prototype.removeUnderscores/capitalize` and `Number.prototype.toDecimalPoint`; their types are declared in `src/app.d.ts`. They are only available where `utils.ts` has been imported.
- **Migrations in CI**: `.github/workflows/main.yml` runs `bun run db:migrate` on every push to `main` (using the `DATABASE_URL` secret). Do not assume the Docker image migrates on build - the current `frontend/Dockerfile` does not (older README text mentions a `RUN bun run db:migrate` line that is no longer present).
- **Deployment**: Fly.io (`redirect/fly.toml` app `kon`, region `dfw`; `frontend/fly.toml` app `kon-dashboard`, region `iad`), both on internal port 3000. A Railway one-click template also exists. Frontend Docker entrypoint is `bun build/index.js`.
- **Bots are filtered from analytics** in the redirect service; when adding analytics logic, respect the existing bot/dedupe short-circuits so redirects stay fast.
- The generated sqlc code in `redirect/db/*.go` carries a `DO NOT EDIT` header - change `query.sql` + schema and regenerate instead.
